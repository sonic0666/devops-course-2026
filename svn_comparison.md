# Git vs SVN

## 1. Почему в Git ветвление "дешёвое", а в SVN — "дорогое"?

В Git ветка — это просто указатель (файл с хешем коммита), создание которого требует
константного времени и почти не занимает места на диске. В SVN ветка физически
реализована как копирование целой директории проекта внутри репозитория, поэтому
создание ветки — это операция копирования данных, которая занимает время и место
пропорционально размеру проекта.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

Нет. SVN — централизованная система: у разработчика есть только рабочая копия файлов,
а вся история хранится на едином центральном сервере. Любой коммит — это сетевой запрос
к серверу, поэтому без подключения к нему закоммитить изменения невозможно. В Git же
каждый клон — это полноценная копия репозитория со всей историей, поэтому коммиты
делаются локально и не требуют сети.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

- Legacy-проекты в госсекторе и банках, где SVN уже глубоко интегрирован в процессы
  и миграция на Git экономически не оправдана.
- Работа с большими бинарными файлами (например, в некоторых пайплайнах геймдева или
  дизайна), где привычна модель блокировки файлов (file locking) вместо merge — SVN
  поддерживает эксклюзивные блокировки "из коробки".
- Организации со строгим требованием единой точки контроля доступа и аудита из
  центрального сервера, без необходимости в распределённой модели.
